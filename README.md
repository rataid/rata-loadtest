# rata-loadtest

Load test scripts for Rata services, run with [Locust](https://locust.io).
New tests are generated by AI (Claude Code) from a filled-in context form, then checked and reviewed.

## Layout

```
rata-loadtest/
├── README.md              this file
├── CLAUDE.md              rules every test follows
├── new-loadtest.mjs       start Claude Code with /new-loadtest (Node, any system)
├── run-local.ps1/.sh      run a test's dashboard locally in Docker
├── tools/
│   └── dryrun.ps1/.sh     run a test's dry run (fake server, no network)
├── .claude/skills/
│   └── new-loadtest/      the /new-loadtest command for Claude Code
└── tests/
    ├── _template/
    │   └── CONTEXT.md     the context form
    └── <test-name>/
        ├── CONTEXT.md       what to test and why (filled-in form)
        ├── locustfile.py    the test
        ├── dryrun_test.py   checks the test against a fake server (tests that write data)
        ├── README.md        how to run it, what to watch, report template
        └── results/         one report per real run
```

The launcher is a Node script, so it runs the same everywhere. The Docker helpers come in two versions with the same
behavior: `.ps1` for Windows (PowerShell) and `.sh` for macOS and Linux (bash); the `.sh` ones also work in Git Bash.

## Create a new test

1. From the workspace folder (with `stackboard` and `rata-dynamic` next to this repo), any system:
   ```bash
   npm run loadtest:new          # needs the workspace package.json below
   node rata-loadtest/new-loadtest.mjs   # same thing, without npm
   ```
   It starts Claude Code in this repo with read access to `stackboard` and `rata-dynamic`, and runs `/new-loadtest`.
   (By hand: `cd rata-loadtest`, `claude`, then type `/new-loadtest`.)

   The workspace folder isn't a repo, so add the npm shortcut yourself: a `package.json` next to `rata-loadtest` with
   ```json
   { "private": true, "scripts": { "loadtest:new": "node rata-loadtest/new-loadtest.mjs" } }
   ```
2. Answer its questions. It starts with the repo and branch (or PR link) of the change, plus one sentence about the
   user action to test; then how many users, how much per user, environment, pass/fail.
   It reads the branch without switching your checkout, finds the requests itself and shows them to you to confirm. Numbers (users, sizes) must come
   from the team or the PM; say "unknown" rather than guessing.
3. It writes `tests/<test-name>/CONTEXT.md` from your answers, asks you to confirm, then writes `locustfile.py`,
   `README.md` (and `dryrun_test.py` for tests that write data or upload files), and runs the checks.

   Already filled in the form by hand (`tests/_template/CONTEXT.md`)? Run
   `npm run loadtest:new -- tests/<test-name>/CONTEXT.md`.
4. **Review** the generated script: how much data it creates, which hosts it calls, the per-user limit.
5. **Rehearse locally** with your own token, 1 user and small values (see "Check a test" below).
6. Ask SRE to load it on the Locust VM.

Without Claude Code, follow the same steps by hand with `CLAUDE.md` and the reference test.

## Check a test

Windows (PowerShell):
```powershell
.\tools\dryrun.ps1 -Test <test-name>                 # fake server only, no network
.\run-local.ps1 -Test <test-name>                    # dashboard at http://localhost:8089
.\run-local.ps1 -Test <test-name> -Version <x.y.z>   # same Locust version as the VM
```

macOS / Linux (bash):
```bash
./tools/dryrun.sh <test-name>                        # fake server only, no network
TEST=<test-name> ./run-local.sh                      # dashboard at http://localhost:8089
TEST=<test-name> VERSION=<x.y.z> ./run-local.sh      # same Locust version as the VM
```

Both need Docker (Docker Desktop on Windows and macOS). The dry run runs with networking off, so it can't reach any real service. Only tests that
write data or upload files have one; read-only tests are checked with a local rehearsal.
`run-local` does send real requests once you start a test, so use sandbox and keep it small.

## Where tests run

Real load tests run on the Locust VM in Singapore (Docker), managed by SRE. Ask them to load a test's `locustfile.py`
and to start Locust with `--class-picker`, so the dashboard runs only the test you choose.
Agree on a time slot with anyone else load testing the same environment, so results don't mix.

## Rules

- **No secrets in this repo.** Tokens are typed into the Locust form for each run. Never commit them, and never pass
  them in the Docker command or environment: values given at startup can be read in the dashboard page source.
- **Sandbox only** unless the team agrees otherwise.
- **Test data must be easy to clean up:** each test uses its own resource key / name prefix, and its README says how
  to find and delete what it created.
- **Save the results** of every real run under the test's `results/` folder (date in the folder name).

See [CLAUDE.md](CLAUDE.md) for the full rules.
